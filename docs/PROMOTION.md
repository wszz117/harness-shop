# 开源项目推广与 Star 增长策略

> 本文是为本仓库维护者准备的**系统化推广打法**。开源项目的 Star 增长本质上是"价值 × 曝光 × 转化"三个变量的乘积：项目本身要解决真问题（价值），要出现在目标人群面前（曝光），落地页要让人 10 秒内看懂并产生收藏冲动（转化）。本仓库在"价值"与"转化"上已经做了充分准备，本文重点给出"曝光"的执行清单。

## 1. 发布前的最后检查（转化率基础）

访客决定是否 Star 的平均时间不超过 10 秒，以下要素直接决定转化率，发布前逐项确认：

| 检查项 | 状态 | 说明 |
|--------|------|------|
| README 首屏有一句话价值主张 + 徽章 + 架构图 | ✅ 已具备 | 首屏即回答"这是什么、为什么值得看" |
| 5 张以上高质量图示 | ✅ 已具备（8 张） | 图比文字的传播效率高一个量级 |
| 双语覆盖 | ✅ README 含英文 About 段 | 建议后续补充完整 README_EN.md 扩大受众 |
| LICENSE + CONTRIBUTING | ✅ 已具备 | 缺 LICENSE 的仓库会被企业用户直接跳过 |
| GitHub 仓库设置 | ⬜ 发布时设置 | About 描述、网站链接、**Topics 标签**（建议：`ai-agents`、`ai-engineering`、`cursor`、`llm`、`workflow`、`code-quality`、`mern`、`bdd`、`tdd`、`developer-tools`） |
| Social Preview 图 | ⬜ 发布时上传 | 用 `docs/images/01-system-architecture.png` 或专门设计的封面图，社交分享时的第一印象 |
| 第一个 Release | ⬜ 发布时创建 | 打 `v1.0.0` tag + Release Notes，让项目显得"在被认真维护" |
| 3—5 个 Good First Issue | ⬜ 发布后创建 | 从 Roadmap 拆出，降低参与门槛，Issue 活跃度是社会证明 |

## 2. 渠道打法：按投入产出比排序

### 第一梯队：技术社区首发（发布后第 1 周）

**中文社区**（本项目文档以中文为主，中文社区是主战场）：

| 渠道 | 打法 | 关键技巧 |
|------|------|---------|
| 掘金 / 思否 | 发深度长文《我给 AI 编码代理装上了"缰绳"：四层防线让 Cursor 不再虚报完成》 | 不要发"项目介绍"，要发"问题—方案—实战"叙事文，文末自然引出仓库 |
| 知乎 | 回答"如何看待 AI 写代码质量不可控""Cursor 使用技巧"类高流量问题 + 发专栏文章 | 回答比文章流量高；用亮点一（证据链）做钩子 |
| V2EX（分享创造节点） | 短帖 + 一张四层防线图 + 链接 | 标题突出"开源了"，正文谦逊、求反馈的姿态转化最好 |
| 微信公众号技术号投稿 | 向"码农翻身""InfoQ""AI 前线"等投稿或自荐 | 一篇爆文可带来数百 Star |
| 开源中国 / Gitee 镜像 | 同步一份 Gitee 镜像，申请 GVP 推荐 | 国内访问快，双平台曝光 |

**英文社区**（白皮书思想有国际竞争力，值得投入）：

| 渠道 | 打法 | 关键技巧 |
|------|------|---------|
| Hacker News（Show HN） | `Show HN: Harness – make AI coding agents prove they're done, not claim it` | 工作日美西早上 8—10 点发；首小时守在评论区认真回复每条评论 |
| Reddit | r/programming、r/ChatGPTCoding、r/cursor、r/ExperiencedDevs | 各 sub 规则不同，先用"讨论帖"姿态而非"宣传帖" |
| X（Twitter） | 发 8—10 条推的 Thread，每条配一张图（8 张图正好） | @ 提及 AI 工程化领域 KOL；结尾放仓库链接 |
| Dev.to / Medium | 英文长文，交叉引用仓库 | 长尾 SEO 流量稳定 |
| Awesome 列表 PR | 向 awesome-ai-agents、awesome-cursor、awesome-llm-tools 等提交收录 PR | 被收录一次 = 持续的被动流量 |

### 第二梯队：持续内容运营（第 2—8 周）

一次性发布的热度约 72 小时，持续增长靠内容连载。建议按"**一个机制一篇文**"拆解成系列（素材全部现成）：hooks 旁路验证的实现细节、19 项硬门禁逐条解读、7 角色契约设计、三库知识工程、示例任务证据链复盘。每篇文章都是一次新曝光，且系列文让读者产生追更与收藏行为。

同时把 README 中的架构图做成一支 3—5 分钟的短视频（B 站 / YouTube：《AI 写的代码怎么管？看这个开源框架的四层防线》），视频是目前获客成本最低的形式。

### 第三梯队：社区与生态（长期）

在 Cursor 官方论坛 / Discord 分享（本项目深度使用其 hooks 与子代理机制，属于官方乐见的社区案例）；关注 AI 工程化、Agent 质量治理相关的会议与播客投稿；与相近项目（如 spec 驱动开发工具）互相引用对比——**对比文既是内容也是 SEO**。

## 3. 时机与节奏建议

| 时间 | 动作 |
|------|------|
| D0 | 发布仓库 + 设置 Topics/About/Social Preview + 打 v1.0.0 Release |
| D1—D3 | 中文社区首发（掘金长文 + V2EX + 知乎回答），集中回复所有评论 |
| D4—D7 | Show HN + Reddit + X Thread（错开中文首发，避免精力分散） |
| W2—W8 | 每周一篇机制拆解文；提交 Awesome 列表 PR；创建 Good First Issues |
| 持续 | 每个 Issue/PR 24 小时内响应——响应速度是新仓库最重要的社会证明 |

## 4. 必须避开的坑

**不要买 Star 或互刷**：GitHub 会清理异常 Star，且刷出来的 Star 曲线（一天暴涨后归零）在 star-history 上一眼可辨，反而摧毁公信力。**不要在别人仓库的 Issue 区打广告**：会被举报 spam。**不要一次性全渠道轰炸**：精力跟不上评论回复，浪费首发窗口。**不要忽视负面反馈**：HN/Reddit 上尖锐的技术质疑认真回复，往往能转化为最有价值的讨论帖，甚至贡献者。

## 5. 衡量指标

用 [star-history.com](https://star-history.com/) 跟踪 Star 曲线；GitHub Insights 的 Traffic 页看访客来源（哪个渠道带来真实流量）；比 Star 更重要的健康指标是：**Clone 数、Issue/PR 参与人数、文档页面停留**——它们代表真实使用而非路过点赞。

> 最后的提醒：所有渠道技巧只放大既有价值。本仓库最锋利的传播钩子是一句话——"**AI 说它做完了，你敢信吗？这个框架让它拿出证据。**"所有渠道的标题与首图都围绕这个钩子展开即可。
