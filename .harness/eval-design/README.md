# 评估设计（Eval Design）

Harness 的有效性需要量化评估，分**过程指标**与**结果指标**两类。

## 过程指标（流程是否被遵守）

| 指标 | 采集方式 | 目标 |
|------|---------|------|
| Hook 旁路覆盖率 | `.hook-results/<task>/` 文件数 / 应触发数 | 100% |
| 一次通过率（Dev 棒不回退） | board 回退记录 | ≥ 70% |
| 模板残留率 | check-harness 模板残留检测 | 0 |
| 心跳规范率 | `[PM]` 行审计 | ≥ 95% |
| TDD 证据完备率 | code-review §3 TDD 证据核对 | 100% |

## 结果指标（交付质量）

| 指标 | 采集方式 | 目标 |
|------|---------|------|
| 测试基线增长 | baseline.json 历史 | 单调不减 |
| E2E 证据完备率 | check-e2e-evidence.py | 100% |
| 交付后缺陷密度 | memory entries 中「症状」溯源 | 下降趋势 |
| Spec 覆盖率 | Scenario 数 / 功能行为数 | ≥ 90% |
| 归档任务返工率 | _archive 后重开任务数 | ≤ 10% |

## 评估节奏

- 每个任务 archive 时自动累计过程指标（脚本待扩展）。
- 每 10 个任务做一次结果指标回顾，写入本目录 `review-YYYY-MM.md`。
